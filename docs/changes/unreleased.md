## Azure VNET connector — `peering_gateway_cxp_id = 0` is treated as unset, and import no longer writes it

A configured `peering_gateway_cxp_id = 0` on `alkira_connector_azure_vnet` now plans the same as an omitted value: the gateway ID in state is kept and sent on update. Read leaves the attribute null when the API returns no gateway, so `terraform plan -generate-config-out` no longer writes `peering_gateway_cxp_id = 0` for a connector without one.

**Impact:** configurations that contain `peering_gateway_cxp_id = 0`, such as those generated by import before a gateway was assigned, no longer plan `<id> -> 0` once the backend assigns a gateway, and updates to a provisioned connector no longer fail with `400 The CXP Peering Gateway of connector '<name>' cannot be updated after it is provisioned.` A configured `0` no longer clears the gateway on an unprovisioned connector; set an explicit ID to change it. If the API stops returning a gateway, state keeps the last known ID instead of `0`. No state migration is required.
