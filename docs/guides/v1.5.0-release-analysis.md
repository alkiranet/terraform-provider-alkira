## E. Backward Compatibility Review

### Risk 1: GCP VPC `export_all_subnets` validation tightened

| Item | Detail |
|---|---|
| **Severity** | **Medium** |
| **Resources** | `alkira_connector_gcp_vpc` |
| **Issue** | `export_all_subnets = false` without `vpc_subnet` blocks now produces a plan-time error. Previously accepted by Terraform (would fail at API). |
| **Who is affected** | Users with this specific invalid configuration. Likely few, since API would have rejected it. |
| **Acceptable for v1.5.0** | Yes. Catches invalid configs earlier. API would have rejected anyway. |
| **Mitigation** | Documented in upgrade instructions. |

**Scenario analysis:**

| Condition | v1.4.4 | v1.5.0 | Compatible |
|---|---|---|---|
| `export_all_subnets = true`, no `vpc_subnet` | Valid | Valid | Yes |
| `export_all_subnets = false`, with `vpc_subnet` | Valid | Valid | Yes |
| `export_all_subnets = false`, no `vpc_subnet` | Accepted (API rejects) | Plan-time error | **No** |
| `export_all_subnets` unset, with `vpc_subnet` | Auto-derived | Auto-derived (false) | Yes |
| `export_all_subnets` unset, no `vpc_subnet` | Default true | Auto-derived (true) | Yes |
| Remove all `vpc_subnet` blocks | API 400 error (bug) | Auto-forces true (fixed) | Yes (fix) |

### Risk 2: Policy prefix list hash function includes `description`

| Item | Detail |
|---|---|
| **Severity** | **Medium** |
| **Resources** | `alkira_policy_prefix_list` |
| **Issue** | `prefixHash` and `prefixRangeHash` now include `description` field. After state migration (TypeList to TypeSet), hash is recomputed. If description was not consistently set, users may see a one-time plan diff. |
| **Who is affected** | Users with existing `alkira_policy_prefix_list` resources, especially those with inconsistent `description` values. |
| **Acceptable for v1.5.0** | Yes. The Read function now always populates `description` (even as empty string) to stabilize hashes. One-time diff at most. |
| **Mitigation** | Documented in upgrade instructions: run `terraform apply` once to stabilize. |

### Risk 3: IP Reservation `prefix` now Computed

| Item | Detail |
|---|---|
| **Severity** | **Low** |
| **Resources** | `alkira_ip_reservation` |
| **Issue** | Adding `Computed: true` allows backend to assign prefix. Users who relied on this being purely user-controlled are unaffected (existing value preserved), but Terraform will no longer error if the field is omitted. |
| **Acceptable for v1.5.0** | Yes |
| **Mitigation** | None needed |

### Risk 4: F5 vServer fields changed from Required to Optional

| Item | Detail |
|---|---|
| **Severity** | **Low** |
| **Resources** | `alkira_service_f5_vserver_endpoint` |
| **Issue** | `fqdn_prefix` and `port_ranges` changed from Required to Optional (needed for ILB type which does not use them). Existing ELB configs still have these fields and are unaffected. |
| **Acceptable for v1.5.0** | Yes |
| **Mitigation** | None needed |

### Risk 5: PAN service Read populates previously empty fields

| Item | Detail |
|---|---|
| **Severity** | **Low** |
| **Resources** | `alkira_service_pan` |
| **Issue** | Read now populates `global_protect_enabled`, `global_protect_segment_options`, `panorama_ip_addresses`, and credential IDs. These were always in the schema but never populated from the API. First refresh after upgrade will add these to state. |
| **Acceptable for v1.5.0** | Yes. Fixes drift detection. No config changes needed. |
| **Mitigation** | Documented in upgrade instructions. |

### Risk 6: Serialization mechanism change in client library

| Item | Detail |
|---|---|
| **Severity** | **Low** |
| **Resources** | All (provider-wide) |
| **Issue** | `sync.Mutex` replaced with buffered channel queue. Requests now wait indefinitely for a queue slot instead of timing out on mutex acquisition. Under high concurrency, this changes failure behavior. |
| **Acceptable for v1.5.0** | Yes. The new mechanism is more correct (timeout applies to HTTP execution, not queue acquisition). |
| **Mitigation** | None needed. Monitor post-release. |

## H. Internal Release Recommendation

### Verdict: GO WITH CAUTION

**Justification:**
- 3 new resources, significant F5 ILB enhancements, and 30+ bug fixes represent substantial customer value.
- State migrations are properly implemented and tested.
- No schema-level breaking changes found (field renames are internal only).
- The 6 reverted commits are cleanly undone with no residual artifacts verified.
- alkira-client-go changes are additive or bugfix-oriented with no compile-time breakage.
- Backward compatibility risks are real but manageable (medium severity at worst).

**Blockers:**
- None remaining. Release notes resource names have been corrected.

**Cautions:**
1. Run `terraform plan` against real infrastructure with GCP VPC connectors and policy prefix lists before tagging.
2. The `export_all_subnets` validation tightening could surface in CI/CD pipelines that have the (previously API-rejected) configuration `export_all_subnets = false` without subnets.
3. Policy prefix list hash change may cause one-time diffs (documented in upgrade instructions).
4. Client library uses a pseudo-version; consider tagging it.

**Follow-up actions for v1.6.0:**
- Re-introduce WriteOnly credential attributes (reverted from this release)
- Re-introduce AWS VPC connector routing Read improvements (reverted from this release)
- Address `GetCredentialById` performance (now fetches all credentials)
